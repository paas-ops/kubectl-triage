# 企业试点指南

kubectl-triage 的开源 CLI **永远可以免费完成一次完整诊断**，不限次数、不强制遥测、不上传证据。
企业试点面向“团队化”需求：团队事故库、评测集管理、审计与私有化部署——用你脱敏的真实历史事故，
验证它在你们环境里的价值，而不是听一段演示。

> 当前为 **M3 Beta**：开源 CLI、可选模型与本地 eval 已就绪；企业 `push` 协议（M4）尚在建设中。
> 试点以共创方式推进，范围、数据处理与验收口径以双方确认的试点协议为准。

## 试点资格

与[拆分计划 §6.3](拆分计划.md)的试点请求资格一致：

- 团队 **≥2 名** SRE / 平台工程师，**≥3 个**集群；
- 有 Prometheus / Alertmanager，能提供 **≥10 起**脱敏历史事故；
- 有团队事故库 / 审计 / 私有部署需求**之一**；
- 接受 **28 天试点**与验收口径。

不满足全部条件也可以先用开源版：`init → analyze → eval` 的流程与试点完全相同，随时可以再申请。
先读[快速开始](quickstart.md)与[安全与数据流](security.md)会显著缩短资格访谈。

## 申请流程

1. **提交申请**：使用 [企业试点申请表](https://github.com/paas-ops/kubectl-triage/issues/new?template=pilot-request.yml)
   （字段定义见 [.github/ISSUE_TEMPLATE/pilot-request.yml](../.github/ISSUE_TEMPLATE/pilot-request.yml)）。
   表单会收集团队规模、集群数、可提供脱敏事故数、监控栈、需求偏好与了解渠道。
2. **资格初筛（3 个工作日内）**：维护者回复并约 30 分钟访谈，确认场景、数据边界、安全/合规要求。
3. **签收试点范围**：共同确认试点目标、时间表、验收口径与数据处理方式。
4. **28 天试点**：
   - 导入 **≥10 起**脱敏历史事故，用开源 CLI 跑通离线诊断与本地 eval；
   - 对团队化能力（事故库 / 评测 / 审计 / 私有化）做场景验证；
   - 每周一次 15–30 分钟同步，记录阻塞与改进项。
5. **复盘与验收**：输出试点结论（可用性、覆盖度、缺口、是否继续），决定是否进入商业合作。

## 试点期间我们看什么

建议的验收口径（具体以签收为准）：

| 维度 | 建议目标 | 验证方式 |
| --- | --- | --- |
| 诊断覆盖 | ≥10 起脱敏事故完成完整流程 | 事故包 + 报告清单 |
| 报告可用性 | 值班/SRE 评审认为“对复盘有帮助” | 人工评分（1–5，≥4 为可用） |
| 性能 | 离线分析 ≤30 秒 / 单次模型运行 ≤5 分钟 | CLI 退出码与耗时 |
| 安全 | 零敏感泄漏、零未授权外传 | 注入/脱敏负例 + 网络审计 |
| 重复使用 | 试点期内同一团队多次主动使用 | 使用记录（不含事故内容） |

开源版本地的 eval 只能作为**确定性回归**证据，不作为统计准确率对外宣传；正式质量结论以试点签收为准。

## 测试数据与安全边界

- **只要脱敏数据**：试点事故在导入前由你们完成脱敏；CLI 的 `validate` / `import` 会做敏感模式扫描
  （`--redact strict` 命中即拒绝，退出码 4），但它是尽力而为的启发式规则，替代不了你们的脱敏流程。
- **开源 CLI 默认零网络**：不传 `--model` 时不发起任何请求；模型模式只访问你们配置的端点
  （可用本地 Ollama），详见[模型模式](model.md)。
- **遥测默认关闭**：即使在企业环境也不强制；字段白名单与关闭方式见
  [安全与数据流](security.md#遥测隐私默认关闭)。
- **数据处理方式**（事故本体的存储、保留、删除）在试点协议中单独约定；仓库文档不构成商业条款。
- 报告与事故包默认只留在本地；是否同步到企业控制平面（M4 `push`）需显式配置。

## 申请前自查（省一次往返）

- [ ] 已用 `go install` 或 Release 二进制跑通[快速开始](quickstart.md)；
- [ ] 能提供 ≥10 起脱敏历史事故（事件/日志/指标摘录即可，不必全量）；
- [ ] 明确最想验证的 1–2 个能力（团队库 / 评测 / 审计 / 私有化）；
- [ ] 安全/合规上有明确的数据出域限制（如有，提前告知）；
- [ ] 有 1 名对接人负责试点节奏与验收。

## 常见问题

**试点收费吗？**
开源 CLI 免费；试点本身是否收费、是否包含部署支持，以双方签收的试点协议为准。

**必须先购买企业版吗？**
不需要。试点用于验证价值；是否采购在试点复盘后决定。

**能只试用开源 CLI 吗？**
可以，而且鼓励：开源版不限次数、功能完整（单次诊断 + 本地 eval + 可选模型）。试点只是在此基础上
增加团队化能力的验证与支持。

**我们的生产日志不能出域。**
纯离线模式满足这一要求：`analyze` 默认不联网；模型模式请用本地 Ollama 或自建网关，并只把端点
指向内网。安全评审清单见[安全与数据流](security.md)。

**试点要准备多少数据？**
≥10 起脱敏事故；建议覆盖至少 2–3 类故障（OOMKilled / CrashLoopBackOff / ImagePullBackOff /
Pending / 发布回归），每起附事件、日志摘录与相关指标。

**申请后多久有回复？**
3 个工作日内初筛回复；访谈通常安排在同一周。
