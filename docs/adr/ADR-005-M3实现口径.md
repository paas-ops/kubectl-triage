| 目的 | 冻结 M3（W8–W10 Beta 分发）的发布工程、文档站与遥测口径 |

## 背景

v0.2.0 已具备离线诊断 + 可选模型 + 本地 eval，但仍只有源码安装路径。M3 的目标是让"装得上、
看得懂、放心用"：预编译产物、校验/签名/SBOM、容器镜像、Homebrew 安装路径、文档站与
opt-in 遥测。本 ADR 冻结实现口径；Beta 发布以 `v0.3.0` 标签触发。

## 决策

### D1 发布产物矩阵（GoReleaser v2）

- `darwin/amd64`、`darwin/arm64`、`linux/amd64`、`linux/arm64`，`CGO_ENABLED=0`，
  单二进制；`ldflags` 注入 `main.version/commit/date`。
- 归档：`kubectl-triage_<version>_<os>_<arch>.tar.gz`，附 README/LICENSE/CHANGELOG。
- **工具版本固定**：GoReleaser 固定 `v2.15.4`（CI `release-check` 与 release workflow 一致）。
  原因：v2.16+ 将 `brews`（Homebrew formula）标记为 deprecated，`goreleaser check` 返回 exit 2；
  在迁移到 `homebrew_casks` 之前固定旧版本以保持 formula 产物与 `check` 门禁。
- 校验：`checksums.txt`（sha256）。
- 产物与 GitHub Release 由 GoReleaser 在 tag 工作流中生成；`dist/` 不入库。

### D2 签名与 SBOM

- 校验文件用 `cosign sign-blob` keyless（GitHub OIDC，`id-token: write`）签名，
  生成 `checksums.txt.sig` + `checksums.txt.pem` 并上传 Release。
- 每个 `tar.gz` 用 `syft` 生成 CycloneDX JSON SBOM（`*.cdx.json`）并上传。
- 容器镜像用 `cosign sign` 对 digest 签名。
- 发布流水线在发布后自校验签名；仓库另提供手动 `verify-release` workflow 对任意已发布 tag
  复验（sha256、证书身份、SBOM 覆盖、GHCR 镜像签名）。

### D3 Docker / GHCR

- `Dockerfile` 多阶段构建：`golang:1.26` 构建 → `gcr.io/distroless/static-debian12:nonroot`
  运行；`ENTRYPOINT ["/usr/local/bin/kubectl-triage"]`。
- 镜像标签：`ghcr.io/paas-ops/kubectl-triage:<version>` + `latest`（tag 发布时推送）。
- 镜像内不包含 kubeconfig/凭据；以 nonroot 运行。

### D4 Homebrew

- GoReleaser 生成 formula（`brews`，`skip_upload: true`），工作流把生成的 `.rb` 作为
  Release 资产上传；tap 仓库 `paas-ops/homebrew-tap` 的自动推送需要独立 PAT secret
  （`HOMEBREW_TAP_GITHUB_TOKEN`），在提供前采用"资产 + 文档 bootstrap"方式。
- 安装路径文档：`brew tap paas-ops/homebrew-tap && brew install kubectl-triage`
  （tap 已建立，`v0.3.0` formula 可用）；`go install` 与 Release 二进制同样受支持。
- 现状（2026-10-30）：tap `paas-ops/homebrew-tap` 已建立并同步 `v0.3.0` formula；后续版本由 tap
  仓库的 `sync-formula` workflow（每日 03:00 UTC + 手动 dispatch）自动同步，使用 tap 自身
  GITHUB_TOKEN，不需要跨仓库 PAT。
- 迁移项：GoReleaser v2.16+ 弃用 `brews`；后续若升级需改用 `homebrew_casks`（安装命令变为
  `brew install --cask`，需同步 docs 与 ADR）。

### D5 文档站

- 静态站点放在 `site/`（无构建步骤），GitHub Pages 通过 `pages` workflow 部署
  （`actions/upload-pages-artifact` + `actions/deploy-pages`）。
- 站点内容：5 分钟快速开始、安装（源码/二进制/Docker/Homebrew）、模型模式、安全与数据流、
  本地评测、企业试点入口。
- 仓库内 Markdown 文档保持为事实源；站点只做入口与摘要。

### D6 遥测（opt-in，默认关闭）

- 默认 **不发送任何数据**。配置位于 `$XDG_CONFIG_HOME/kubectl-triage/config.yaml`
  （可用 `KUBECTL_TRIAGE_CONFIG_DIR` 覆盖）；首次 analyze 若未配置，仅打印一行提示
  "匿名统计默认关闭，启用：kubectl-triage telemetry enable"，不交互询问。
- 命令：`kubectl-triage telemetry status|enable|disable`。
- 端点：`KUBECTL_TRIAGE_TELEMETRY_URL`；未配置端点时事件丢弃（不落盘、不重试）。
- 事件字段白名单（缺一不可、多一不可）：
  `install_id, event, version, os, arch, mode, fault_class, duration_ms, evidence_count, outcome`。
- **绝不采集**：集群名、命名空间、告警名、日志/证据正文、模型 key、文件路径、主机名。
- 发送为 best-effort：2s 超时、失败静默、不阻塞分析；`KUBECTL_TRIAGE_TELEMETRY=off`
  强制关闭。
- 隐私说明写入 `docs/security.md`；测试用 httptest 断言字段白名单与默认零请求。

### D7 版本与发布流程

- M3 发布 `v0.3.0`（Beta）：tag push 触发 `release` workflow，GoReleaser 创建 Release
  并上传产物；CI 在 PR 阶段执行 `goreleaser check` 与 Docker 构建冒烟，避免坏配置进入 tag。
- Homebrew tap / 遥测端点属外部依赖，缺失不阻塞本地与 Release 产物。

### D8 CI 门禁（新增）

- `release-check`：`goreleaser check`。
- `docker-build`：`docker build` 冒烟（不推送）。
- `verify-release`（手动）：对已发布 tag 复验签名/SBOM/镜像；release workflow 内部也会自校验。
- 既有 `test` 与 `cross-build` 矩阵保持。

## 后果

- 代码：`internal/telemetry`（新）、`internal/cli/telemetry.go`（新命令）、CLI 事件埋点。
- 工程：`.goreleaser.yaml`、`Dockerfile`、`.dockerignore`、`.github/workflows/release.yml`、
  `.github/workflows/pages.yml`、CI 新增两个 job。
- 文档：`site/`、`docs/install.md`、`docs/homebrew.md`、`docs/quickstart.md`、
  `docs/security.md`、`docs/pilot.md`、pilot issue 模板、README/CHANGELOG 更新。
- 验证：v0.3.0 tag 后检查 Release 资产（4 二进制 + checksums + sig/pem + 4 SBOM + formula）、
  GHCR 镜像与签名、Pages 站点可访问；遥测默认零请求。
