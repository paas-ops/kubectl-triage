| 项 | 内容 |
| --- | --- |
| 状态 | 已接受（Accepted） |
| 日期 | 2026-10-30 |

| 目的 | 冻结 M1 并行实现（契约/CLI、导入器、规则/报告）共享的落地口径 |

## 背景

M1 要把"一次本地诊断"闭环：证据规范化、五类规则、双格式报告、12 个 golden、退出码。
三名实现者并行工作时，若证据字段、退出码、裁剪与校验口径不先冻结，会在集成期返工。
本 ADR 记录已落地的实现口径；与 ADR-002 共同构成 M1 契约。

## 决策

### D1 证据模型与 content_ref

- evidence item 字段与 `pkg/schema/report.schema.json` 一致：`id, source, observed_at, collected_at,
  summary, content_ref, sha256, stale`，可选 `query/redaction/skew_seconds`。
- content_ref 命名：整文件 `<rel>`；JSON 条目 `<rel>#items/<n>`；日志行 `<rel>#L<行号>`。
- `observed_at` 优先取内容内时间（事件 lastTimestamp/firstTimestamp、日志首行时间戳、
  metrics 数值秒），取不到回退 `incident.observed_at`；`collected_at` 统一取 `incident.collected_at`。
- stale：观察/采集时间距分析时刻 >15 分钟；时钟偏差 |collected−observed| >9 秒时记 `skew_seconds`。

### D2 证据裁剪（--max-evidence）

- 默认 200。按"来源优先级 → observed_at → id"确定性取前 N，再按 observed_at、id 排序输出。
- 被裁剪项写入报告 `limitations`（数量与来源），保证报告可解释。

### D3 退出码

- 0 成功；1 输入/配置错误（含 `--offline` 与 `--model`（非 none）同时给出；`--offline --model none` 合法）；
  2 `--fail-on-missing` 触发（missing_data 非空或无 hypotheses）；
  3 模型不可用 → 离线报告 + `degraded: true`；4 安全校验失败。
- 退出码优先级：`--fail-on-missing`（2）与模型降级（3）同时满足时返回 2，显式 CI 门禁优先。
- M1 未实现模型提供方：`--model` 非 `none` 走退出码 3；M2 接入真实 provider 后语义不变。

### D4 脱敏模式

- `strict`（默认）：validate/analyze 命中敏感模式 → 退出码 4，错误不回显原值。
- `standard`：validate 警告放行；分析时 `bundle.ReadFile` 对内容做 `redact.Scrub`（`[REDACTED]`），
  报告不回显。
- `off`：跳过扫描，仅供调试。

### D5 schema 校验

- 不引入外部 JSON Schema 库：手写子集校验器（`$ref/type/required/properties/additionalProperties/
  items/enum/const/minLength/minimum/maxItems/minItems/format=date-time`），schema JSON 通过
  `//go:embed` 成为唯一事实源。原因：沙箱/离线环境不可下载模块，且 CI 不增加依赖。
- analyze 生成报告后二次校验；`report` 命令渲染前校验；golden 期望报告在测试中校验。

### D6 golden 布局

- `testdata/golden/<case>/`：`incident.yaml` + 证据文件 + `expected/report.json`。
- 12 例 = 五类×2 + missing + injection；比较前归一化 `generated_at` 与 `versions.cli`；
  同一输入两次运行必须一致（除 generated_at）。
- 注入包断言报告不含外传 URL/命令；缺失包断言 hypotheses 为空且 missing_data 非空。

### D7 import 命令

- `kubectl-triage import <source> <dir> [--from <file>] [--name <name>] [--force]`；默认从 stdin 读；
  只写事故包标准目录（alert.json / k8s/* / metrics/* / logs/*）；不覆盖已有文件除非 `--force`；
  `--name` 用于 metrics/logs 命名。
- 产物形态（供 analyze 消费）：
  - alertmanager → `alert.json`：`{status, alerts:[{status,labels,annotations,startsAt,endsAt,generatorURL,fingerprint}]}`，按 startsAt/fingerprint/labels 排序，时间 RFC3339Nano UTC；
  - kubectl → `k8s/events.json`（`EventList`）+ `k8s/pods.yaml` / `k8s/deployments.yaml`（`kind: List`，items 保留各自 `kind: Pod|Deployment`）；
  - prometheus → `metrics/<name>.json`（保留 `status/data{resultType,result}`）；
  - loki → `logs/<name>.log`（每行 `RFC3339 {k="v",...} <line>`，按时间/标签排序，行内换行转义为字面 `\n`）。
- import 在写入前对输入做敏感扫描（复用 `redact.Scrub` 比对）；命中则退出码 4 且不写入任何文件（需求文档 §8）。

### D9 analyze --out 语义

- 为空：写入事故包目录（`report.json` / `report.md`）；
- 目录路径（不存在则递归创建）：目录内写 `report.json` / `report.md`；
- 单一 `--format` 且 `--out` 以对应扩展名结尾：写入该文件；
- `--format=both` 且 `--out` 指向文件、或扩展名与格式不符：退出码 1。

### D8 CI 门禁

- gofmt 检查 + build + vet + test（schema/golden 校验在测试内）+ darwin/linux × amd64/arm64
  交叉编译矩阵。
- golangci-lint 等增强 lint 留到 M3 分发阶段；当前以 gofmt + vet 作为最小等价门禁。

## 后果

- 代码结构按 Epic A/B/C 落地，文件写作用域互不重叠。
- 未决：模型接入细节（M2）、本地 eval harness（E1）、企业 push 协议（M4）。
