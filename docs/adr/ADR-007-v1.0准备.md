# ADR-007：v1.0 准备——schema 兼容、跨平台与正式评测集校验

| 项 | 内容 |
| --- | --- |
| 状态 | 已接受（Accepted） |
| 日期 | 2026-10-30 |
| 关联 | [需求文档](../需求文档.md) §5/§6/§9/§11、[拆分计划](../拆分计划.md) §5.3、[ADR-002](ADR-002-契约口径.md)–[ADR-006](ADR-006-M4实现口径.md) |
| 目的 | 为 v1.0 的兼容承诺做工程准备：冻结 schema 兼容边界、补齐 Windows 构建、提供正式评测集校验器 |

## 背景

v0.1–v0.4 已完成离线诊断、可选模型、本地 eval、分发与企业 push 客户端。对外宣布 v1.0 前需要
遵守需求 §5.3 的兼容承诺（"v1.0 后 schema 至少兼容一个大版本"），因此先把兼容性测试、跨平台
产物与正式评测集接口补齐；v1.0 仍需真实盲测集与运营数据支撑，本 ADR 只做工程准备。

## 决策

### D1 schema 版本与兼容策略

- 报告的 `schema_version` 固定 `1.0`；`incident.yaml` 契约无独立版本号，随报告契约同步演进。
- **v0.x**：允许破坏性变更，但必须在 CHANGELOG 记录并提供迁移说明。
- **v1.0 起**：schema 至少兼容一个大版本；允许**新增可选字段**（不破坏旧消费者），
  删除字段、收紧枚举/必填、变更语义等属破坏性变更，必须提升主版本（`2.0`）并提供迁移说明。
- eval JSON 契约（`kind=eval|eval-set`，`version=1.0`）独立于报告 schema 版本，同样遵循上述规则。

### D2 兼容性测试（回归门禁）

- 在 `pkg/schema` 增加兼容性基线测试：把两份 schema 的**必填字段、枚举值、const、顶层结构**
  提取为基线文件（`pkg/schema/testdata/compat-baseline.json`）；schema 变更导致基线不同时测试
  失败，必须显式更新基线并在 CHANGELOG/ADR 说明变更类型（新增可选字段 / 破坏性变更）。
- 12 个 golden 的 expected/report.json、examples 报告必须始终能通过当前 schema 校验
  （既有测试保持）；schema 校验器自身不得放宽为"只检查部分字段"。
- 任何破坏性 schema 变更在 v0.x 允许，但必须同时更新基线、CHANGELOG 与迁移说明。

### D3 Windows 支持

- 发布产物新增 `windows/amd64`（`go build` 支持 `windows/arm64`，但首发只承诺 amd64）；
  归档格式为 zip（`format_overrides`），文件名规则与其它平台一致。
- CI 增加 `windows-latest` 测试 job（`go build ./...` + `go test ./...`），跨平台矩阵保留；
  Windows 上必须零网络、路径处理正确、无 Unix-only 假设。
- 文档更新平台矩阵与安装说明；Windows 与 macOS/Linux 的功能边界一致（模型/推送同样 opt-in）。

### D4 正式评测集校验器（E4 接口）

- `kubectl-triage eval <cases-dir> --validate [--min-cases N] [--json]`：**只校验集合、不运行分析**。
- 校验项：用例发现规则、incident.yaml 与 expected/report.json 可解析并通过各自 schema 校验、
  用例名唯一、期望报告与证据中不含凭据模式（复用 `internal/redact`）、总数 ≥ `--min-cases`
  （正式集建议 100）。
- 输出稳定 JSON：`kind="eval-set"`、`version="1.0"`、`cases[{name,valid,errors[]}]`、
  `summary{total,valid,invalid,min_cases_required}`，确定性、无时间戳；
- 退出码：0 全部有效且数量达标；1 输入/配置错误；2 存在无效用例或数量不足。

### D5 版本与发布

- 本阶段发布 `v0.5.0`（v1.0 准备）：新增 Windows 产物、schema 兼容基线、评测集校验器；
  发布流程沿用 release workflow（含自校验）与 tap 自动同步。
- v1.0 的宣布条件另行评审：正式 100 例盲测集、试点数据与兼容基线全部就绪。

### D6 实现澄清（v0.5.0）

- **发布资产（v0.5.0 起共 14 个文件）**：5 归档（4×`tar.gz` + `kubectl-triage_<ver>_windows_amd64.zip`）
  + `checksums.txt` + `.sig` + `.pem` + 5×SBOM（每个归档一个 `.cdx.json`）+ `kubectl-triage.rb`。
  Windows 仅发布 amd64；`kubectl-triage.exe` 无 Authenticode 签名，文档要求先校验 sha256/cosign，
  再按 SmartScreen 提示运行。
- **工作流**：release workflow 的 SBOM 循环覆盖 `*.tar.gz` 与 `*.zip`；verify-release 下载
  含 `*.zip` 并强制每个归档的 SBOM 覆盖；checksums 覆盖全部 5 个归档。
- **Windows CI**：新增 `windows-test` job（`go build ./...` + `go test ./...`）与 cross-build
  `windows/amd64`；checkout 前 `core.autocrlf=false` 以保护逐字节 golden；telemetry 测试做跨平台
  断言（Unix 保留 0600 断言，Windows 改断言普通文件 + 内容可读）。
- **eval --validate**：候选用例 = 目录含 `incident.yaml` **或** `expected/report.json`（以便报出
  半成品用例）；`--min-cases` 单独使用 → 退出 1；validate 模式忽略 `--now` 与模型 flags。
- **schema 兼容基线**：默认严格比较；有意的契约变更必须 `UPDATE_COMPAT=1 test ...` 重生成、
  review diff 并在 CHANGELOG/ADR 记录变更类型；基线文件禁止手改。

- 代码：`pkg/schema`（兼容基线测试）、`internal/eval`（集合校验 + 测试）、`internal/cli/eval.go`
  （--validate/--min-cases）、`.goreleaser.yaml`（windows zip）、`.github/workflows/ci.yml`
  （windows job）。
- 文档：`docs/schema.md`（契约与版本策略）、install（Windows）、eval/eval-contract（校验器）、
  README/站点更新。
- 验证：本地 goreleaser snapshot 产出 windows zip；CI windows job 通过；`eval --validate`
  对 12 golden 通过、对构造的坏集合返回 2。
