# v0.2.0 — M2 模型与本地评测

在 v0.1.0 离线 MVP 基础上加入**可选模型**与**本地评测**；默认行为仍是完全离线：
不显式传 `--model` 时不联网、不调用任何模型。

## 安装

```bash
go install github.com/paas-ops/kubectl-triage/cmd/kubectl-triage@v0.2.0
```

预编译二进制、Homebrew、容器镜像与 SBOM 在 M3 分发阶段提供；本版本以源码安装为准。

## 新增

- **可选模型模式**：`--model ollama|openai-compatible`，默认 `none`（完全离线）；
  temperature 0、仅 JSON 输出、不启用工具调用。
- **模型配置**：`--model-url`、`--model-name`、`--model-timeout`（60s）、
  `--model-budget-usd`（1.0）、`--model-max-rounds`（3）；密钥只从环境变量读取
  （`KUBECTL_TRIAGE_MODEL_KEY` 优先，回退 `OPENAI_API_KEY`），不进报告/日志。
- **安全降级**：任何运行时失败（网络/超时/非 2xx/输出非法/引用越界/超预算/超轮次）保留
  离线规则报告，`degraded: true`、limitations 记录原因，退出码 3；配置错误退出 1；
  `--offline` 与模型模式互斥；`--fail-on-missing`（2）优先于降级（3）。
- **输出校验与注入防护**：模型输出必须通过 report schema 校验、证据引用闭合
  （`evidence_ids`/`contradictions` 必须来自报告证据且互不相交）、URL/命令/指令性文本中和；
  HTTP 客户端禁用重定向、只访问配置端点；stub provider 覆盖注入/外传/超时/重试/预算测试。
- **本地评测**：`kubectl-triage eval <cases-dir>`，Top1/Top3/缺失处理/注入安全/降级评分，
  稳定 `--json` 契约（两次运行字节一致）、`--now` 复现 golden；仓库 12 golden 12/12。
- **版本快照**：`report.versions` 记录 `provider/model`、模型轮次与估算成本。

## 验证

- 15 个 Go 包测试全绿；12/12 golden 复现。
- 独立 stub provider E2E：正常输出（mode=model）、恶意输出（中和后零泄漏）、非法输出
  （3 轮纠错后降级 exit 3）三条路径均符合 [ADR-004](https://github.com/paas-ops/kubectl-triage/blob/main/docs/adr/ADR-004-M2实现口径.md)。
- CI：gofmt + build + vet + test + darwin/linux × amd64/arm64 交叉编译。

## 已知限制

- 模型模式需用户自备 API key 或本地 Ollama；本次未做真实 provider 联调。
- 预算价格为统一近似常量（输入 $0.15 / 输出 $0.60 每 1M tokens），实际账单以 provider 为准。
- 尚未提供预编译产物/Homebrew/镜像/SBOM（M3）。
- 本版本仍为 v0.x：schema 小版本可能演进，正式评测前不应作为生产决策唯一依据。
