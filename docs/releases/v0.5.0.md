# v0.5.0 — M5 v1.0 准备

第五个里程碑版本：为 v1.0 的兼容承诺做工程准备——schema 兼容门禁、Windows 支持、正式评测集校验器。
不包含破坏性变更；离线默认、报告契约与既有命令行为保持不变。

## 安装

```bash
# 源码
go install github.com/paas-ops/kubectl-triage/cmd/kubectl-triage@v0.5.0

# 预编译（本 Release：darwin/linux × amd64/arm64 + windows/amd64）
# Windows：下载 kubectl-triage_0.5.0_windows_amd64.zip，解压后把 kubectl-triage.exe 放入 PATH
# Docker
docker run --rm ghcr.io/paas-ops/kubectl-triage:v0.5.0 version
# Homebrew（tap 自动同步）
brew tap paas-ops/homebrew-tap && brew install kubectl-triage
```

## 本版本新增

- **Windows 支持**：新增 `windows/amd64` zip 产物（内含 `kubectl-triage.exe` + README/LICENSE/
  CHANGELOG）；CI 新增 `windows-latest` 构建 + 测试 job；功能与 macOS/Linux 一致（默认离线、
  模型/push 同样 opt-in）。exe 无 Authenticode 签名，安装前请先校验 sha256/cosign。
- **schema 兼容门禁**：`pkg/schema` 基线测试固定 incident/report 契约的必填字段、枚举与 const；
  有意变更必须显式 `UPDATE_COMPAT=1` 重生成基线并记录迁移说明；12 个 golden 与示例报告持续
  通过当前 schema。契约与版本策略见 [docs/schema.md](https://github.com/paas-ops/kubectl-triage/blob/main/docs/schema.md)。
- **正式评测集校验器**：`kubectl-triage eval <cases-dir> --validate [--min-cases N] [--json]`，
  只校验不分析：schema、用例名唯一、凭据扫描、用例数量（正式 100 例建议 `--min-cases 100`）；
  输出稳定 `eval-set` JSON，退出码 0/1/2。
- **发布资产（14 个）**：5 归档 + checksums/sig/pem + 5 SBOM + formula；SBOM 与
  `verify-release` 覆盖包含 Windows zip。

## 校验

```bash
sha256sum -c checksums.txt              # macOS: shasum -a 256 -c checksums.txt
cosign verify-blob checksums.txt --certificate checksums.txt.pem --signature checksums.txt.sig \
  --certificate-identity-regexp 'https://github.com/paas-ops/kubectl-triage/.github/workflows/release.yml@refs/tags/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Windows PowerShell：`Get-FileHash .\\kubectl-triage_0.5.0_windows_amd64.zip -Algorithm SHA256`；
cosign 校验同上。或直接复跑 `verify-release` workflow。

## 已知限制

- 官方对 Windows 只承诺 amd64；未做 Windows 实机手工验收（CI 已跑构建+测试）。
- 100 例正式盲测集仍待建设（`--validate` 提供集合校验能力，数据本身由运营/企业侧提供）。
- 企业事故库/评测/审计等服务端能力仍不在本仓库（见 docs/enterprise.md）。
- v0.x：schema 小版本可能演进；v1.0 宣布前请以兼容基线与评测数据为准。
