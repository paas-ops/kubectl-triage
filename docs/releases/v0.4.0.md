# v0.4.0 — M4 企业桥（push 客户端）

第四个里程碑版本：在保持离线默认的前提下，提供**显式 opt-in** 的企业推送客户端与公开协议
（protocol v1.0）。企业事故库、评测、审计、私有部署等服务端能力不在本仓库（见 docs/enterprise.md）。

## 安装

```bash
# 源码
go install github.com/paas-ops/kubectl-triage/cmd/kubectl-triage@v0.4.0

# 预编译（本 Release 资产，4 平台）
# Docker
docker run --rm ghcr.io/paas-ops/kubectl-triage:v0.4.0 version
# Homebrew（tap 自动同步）
brew tap paas-ops/homebrew-tap && brew install kubectl-triage
```

## 本版本新增

- **`push <dir>` 企业推送客户端**：默认关闭；必须显式配置 `--endpoint`（或
  `KUBECTL_TRIAGE_ENTERPRISE_ENDPOINT`）与 `KUBECTL_TRIAGE_ENTERPRISE_TOKEN` 才联网。
- **协议 1.0**：`POST {endpoint}/v1/push`，payload 含完整 `report.json` + `report_sha256` +
  证据哈希（默认不上传证据正文）；`--include-evidence` 才附带脱敏事故包的确定性 tar.gz。
- **可靠性**：`push_id`/Idempotency-Key 幂等、网络/429/5xx 重试（共 3 次尝试）、4xx 不重试、
  整体 30s 预算；`--dry-run` 零网络预览，`--out` 可落盘 payload 供审计。
- **安全**：TLS 强校验、禁用重定向、令牌仅环境变量、推送前 schema + 凭据模式双重检查；
  命中敏感内容退出码 4 且不发送。
- **公开协议文档**：docs/push-protocol.md（服务端实现契约）、docs/enterprise.md（开源/商业边界）、
  docs/pilot-playbook.md（28 天试点运营）、docs/metrics.md（安装→激活→重复→试点漏斗）。
- **发布流水线自校验**：release workflow 发布后自验签名；另有 `verify-release` 可对已发布 tag 复验。

## 校验

```bash
sha256sum -c checksums.txt
cosign verify-blob checksums.txt --certificate checksums.txt.pem --signature checksums.txt.sig \
  --certificate-identity-regexp 'https://github.com/paas-ops/kubectl-triage/.github/workflows/release.yml@refs/tags/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

或直接复跑本仓库的 `verify-release` workflow。

## 已知限制

- 推送服务端（企业事故库/去重/审计）在商业版实现，不在本仓库；`push` 仅提供客户端协议。
- 遥测官方统计端点未提供（未配置 endpoint 时事件丢弃）。
- Homebrew formula 由 tap 仓库 workflow 自动同步（每日/手动）。
- v0.x：schema 小版本可能演进，正式评测前不应作为生产决策唯一依据。
