# v0.1.0 — M1 离线 MVP

首个里程碑版本：离线优先、本地运行的 Kubernetes 事故诊断 CLI。把一份脱敏事故包变成
可复现、可追溯、可评审的 Markdown/JSON 报告，不依赖控制平面、不上传证据。

## 安装

```bash
go install github.com/paas-ops/kubectl-triage/cmd/kubectl-triage@v0.1.0
```

预编译二进制、Homebrew、容器镜像与 SBOM 在 M3 分发阶段提供；本版本以源码安装为准。

## 亮点

- 六个命令：`init` / `import` / `validate` / `analyze` / `report` / `version`，退出码 0/1/2/3/4。
- 五类故障确定性规则：OOMKilled、CrashLoopBackOff、ImagePullBackOff、Pending、发布回归
  （rule-v0.2）；每条结论引用证据，并给出反证与置信分层。
- 证据规范化：`content_ref`（如 `k8s/events.json#items/0`）、观察/采集时间分离、stale（>15 分钟）、
  真正的时钟偏差（观察时间晚于采集时间 >9 秒）与采集延迟提示。
- 严格契约：`incident.yaml` 与 `report.json` 均通过内嵌 JSON Schema 校验（零外部依赖）；
  Markdown 与 JSON 同源渲染。
- `import alertmanager|kubectl|prometheus|loki`：确定性归一化输出；导入时扫描凭据，
  命中退出 4 且不写入任何文件。
- 默认离线、只读：不读取 Secret、不执行集群写操作、不联网；`--redact strict|standard|off`。
- 12 个 golden 事故包（五类×2 + 缺失 + 注入）+ 确定性、注入、反证不相交断言。

## 验证

- `go test ./...`：13 个包全绿；12/12 golden 严格比对通过。
- CI：gofmt + build + vet + test + darwin/linux × amd64/arm64 交叉编译。
- `init → analyze` 首次诊断开箱即得 high 置信、无 stale 的报告。

## 已知限制

- 模型模式（`--model`）尚未实现：请求时回退离线规则并返回退出码 3（M2）。
- `eval` 本地评测（M2）、企业 `push`（M4）未实现。
- 本版本为 M1 离线 MVP；正式评测前不应作为生产决策唯一依据。
